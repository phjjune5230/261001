# RULE — 앞으로 지킬 것

코딩하기 전에 읽는 문서입니다. "이미 된 일"은 여기 안 씁니다.
각 규칙에는 **왜**를 붙였습니다. 이유를 모르면 규칙을 우회하게 되고, 우회하면 버그가 됩니다.

---

## 1. 보안

### `NEXT_PUBLIC_`은 함부로 붙이지 않는다
붙이면 그 값이 **브라우저 JS 번들에 평문으로 인라인**됩니다. 공개된 것과 같습니다.
`SUPABASE_SERVICE_ROLE_KEY`는 DB 권한을 완전히 우회하므로 절대 대상이 아닙니다.

### 서버 전용 모듈은 클라이언트에서 import하지 않는다

| 모듈 | 이유 |
|------|------|
| `lib/auth.ts` | `APP_PIN` / `APP_TOKEN`을 읽습니다 |
| `lib/db-server.ts` | `SUPABASE_SERVICE_ROLE_KEY`를 읽습니다 |

`server-only` 패키지를 붙이고 싶지만 아직 미설치입니다. 그래서 **규칙으로 막습니다.**
모듈을 하나 추가하면 이 표에도 반드시 한 줄을 넣으세요 — 빠뜨린 규칙은 없는 규칙입니다.

### 제공자의 원본 응답을 브라우저로 보내지 않는다
키 지문이 포함될 수 있습니다. 원본은 서버 콘솔에만 남기고, 클라이언트에는
짧은 한국어 메시지만 보냅니다. 허용 목록은 `app/api/chat/route.ts`에 있습니다.

### 인증은 본문 파싱보다 먼저 검사한다
`req.json()` 전에 `x-app-token`을 봅니다. 인증 전에 본문을 읽을 이유가 없습니다.

## 2. 단일 출처

중복은 반드시 어긋납니다. 실제로 provider 개수가 문서·코드·화면에 흩어져
"4개"라고 잘못 적힌 일이 있었습니다. **정의는 한 곳에만.**

| 무엇 | 유일한 출처 |
|------|-------------|
| 모델 목록 | `lib/models.ts` |

| 환경 변수 이름 | `.env.example` + Vercel 환경 변수 |
| 스키마 | `supabase/*.sql` |

## 3. 디자인

다크 전용. 밝은 모드는 계획에 없습니다.

| 용도 | 색상 | 실제 쓰임 |
|------|------|----------|
| 배경 | `#0f0f0f` | 페이지 |
| 입력 배경 | `#151515` | 인풋 · 셀렉트 |
| 말풍선 | `#181818` | AI 말풍선 |
| 경계선 | `#222` | `border-[#222]` |
| 보조 텍스트 | `#555` | 설명 · 라벨 |
| 강조색 | `#e8ff47` | 활성 상태 · 버튼 · 포커스 |
| 에러 | `#ef4444` | 잠금 실패 · API 오류 |

폰트는 Syne(제목) / DM Mono(본문) 둘 다 `next/font/google`입니다.

**`next/font`는 리터럴 폰트 이름을 노출하지 않습니다. CSS 변수로만 접근합니다.**

```tsx
// ❌ 동작하지 않음
style={{ fontFamily: "'Syne'" }}
// ✅
style={{ fontFamily: 'var(--font-syne), sans-serif', fontWeight: 700 }}
```

### 에러를 말풍선에 넣지 않는다
provider의 원본 JSON이 AI 대답처럼 보이던 것을 막기 위한 것입니다.
에러는 `#ef4444` 계열의 **별도 영역**에 표시하고, AI 말풍선과 절대 섞지 않습니다.

## 4. 코드

- **TypeScript 필수.** `any` 지양. 명시적 타입.
- 페이지 파일은 `'use client'`를 명시적으로 붙입니다.
- `app/layout.tsx`에 `'use client'`를 붙이지 않습니다. 하위 트리 전체가
  클라이언트 렌더링으로 바뀌고 `metadata`를 쓸 수 없게 됩니다.
- 코드가 이미 말하는 것을 문서에 다시 쓰지 않습니다. 중복은 반드시 어긋납니다.

## 5. 문서

**이 저장소의 문서는 3개입니다 (`README.md` + `docs/` 2개).** 새로 늘리지 않습니다.

- **합계 400줄을 넘으면 그때 의심하세요.** 넘었다면 삭제할 게 있다는 뜻입니다.
- 지금이라도 **파일에 없는 것은 문서에 쓰지 않습니다.** 정의를 옮겨 적는 것이지,
  이미 코드에 있는 것을 옮겨 적는 것이 아닙니다.
- **판단 근거는 코드가 있는 자리에 둡니다.** 되돌릴 만한 판단일수록
  그 판단을 내린 코드 옆에 이유를 씁니다 (`components/AuthGate.tsx`가 예입니다).
  문서와 코드가 갈라지면 문서가 먼저 거짓말이 됩니다.

## 6. 커밋과 버전

- 브랜치 `master`. 혼자 쓰는 개인 저장소라 분기 이력은 필요 없습니다.
- 커밋 메시지: `v{버전} {요약}`
- **판단이 필요하면 코드를 고치기 전에** 그 판단이 들어갈 코드 옆에 적습니다.
- 검증은 `npm run lint`(경고 0) · `npx tsc --noEmit` · `npm run build` 통과 후에만.
- 커밋 전에 `git status`에 `.env` / `.env.local`이 없는지 확인합니다.

| 버전 올릴 때 | 기준 |
|--------------|------|
| patch | 버그 수정, 문서 정정 |
| minor | 기능 추가 |
| major | API 계약처럼 호환성이 깨지는 변경 |

`package.json`의 `version`이 기준이고, 같은 문자열로 git 태그를 붙입니다.
