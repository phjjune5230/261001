# RULE — 앞으로 지킬 것

코딩하기 전에 읽는 문서입니다. "이미 된 일"은 여기 안 씁니다.
각 규칙에는 **왜**를 붙였습니다. 이유를 모르면 규칙을 우회하게 되고, 우회하면 버그가 됩니다.

---

## 1. 보안

### `NEXT_PUBLIC_`은 함부로 붙이지 않는다
붙이면 그 값이 **브라우저 JS 번들에 평문으로 인라인**됩니다. 공개된 것과 같습니다.
`SUPABASE_SERVICE_ROLE_KEY`는 DB 권한을 완전히 우회하므로 절대 대상이 아닙니다.

### 서버 전용 모듈은 클라이언트에서 import하지 않는다

| 모듈 | 이유 |
|------|------|
| `lib/auth.ts` | `APP_PIN` / `APP_TOKEN`을 읽습니다 |
| `lib/db-server.ts` | `SUPABASE_SERVICE_ROLE_KEY`를 읽습니다 |
| `lib/compaction.ts` | `lib/db-server.ts`를 거칩니다 |
| `lib/model-registry.ts` | `lib/db-server.ts`를 거칩니다 |

`server-only` 패키지를 붙이고 싶지만 아직 미설치입니다. 그래서 **규칙으로 막습니다.**
모듈을 하나 추가하면 이 표에도 반드시 한 줄을 넣으세요 — 빠뜨린 규칙은 없는 규칙입니다.

### 제공자의 원본 응답을 브라우저로 보내지 않는다
키 지문이 포함될 수 있습니다. 원본은 서버 콘솔에만 남기고, 클라이언트에는
짧은 한국어 메시지만 보냅니다. 허용 목록은 `app/api/chat/route.ts`에 있습니다.

### 인증은 본문 파싱보다 먼저 검사한다
`req.json()` 전에 `x-app-token`을 봅니다. 인증 전에 본문을 읽을 이유가 없습니다.

## 2. 단일 출처

중복은 반드시 어긋납니다. 실제로 provider 개수가 문서·코드·화면에 흩어져
"4개"라고 잘못 적힌 일이 있었습니다. **정의는 한 곳에만.**

| 무엇 | 유일한 출처 |
|------|-------------|
| 모델 목록 | `lib/models.ts` |
| 색상 · 폰트 · 간격 · 모서리 · 타입 크기 | **`app/globals.css` 의 `@theme` 토큰** |
| 밝은/어두운 테마의 색 값 | `app/globals.css` 의 `:root` 와 `:root[data-theme='dark']` |
| 환경 변수 이름 | `.env.example` + Vercel 환경 변수 |
| 스키마 | `supabase/*.sql` |

토큰이 생기기 전에는 색이 `bg-[#0f0f0f]` 형태로 화면마다 복붙되어 있었다.
이제 **`bg-[#...]` 형태의 하드코딩은 새지 않습니다.** 필요한 값이 없으면
`@theme` 에 토큰을 추가하고, 이름으로 씁니다.

### 테마를 바꿀 때 색 토큰에 손대지 않는다 (v0.18.0)

색 값은 `@theme` 안에 **아니라** `:root` / `:root[data-theme='dark']` 에 있습니다.
`@theme inline`은 그 변수를 참조만 합니다.

`@theme` 안에 값을 그대로 적으면 Tailwind가 `bg-page`를 `#f7f7f5`로 만들어
버려서 테마 전환이 동작하지 않습니다. **색은 항상 두 테마 쌍으로**, 같은 이름으로
써야 합니다 — 한쪽에만 넣으면 다른 테마에서 그 토큰이 사라집니다.

`body { background: var(--color-page) }` 처럼 토큰을 직접 참조할 때도
`var(--page)` 를 써야 합니다. `@theme inline`은 `--color-*` 변수를 루트에
남기지 않으므로(값이 유틸리티에 인라인됩니다) `var(--color-page)` 는
해결되지 않고 투명해집니다.

## 3. 디자인

다크 전용. 밝은 모드는 계획에 없습니다.

**값은 전부 `app/globals.css` 의 `@theme` 토큰입니다.** 여기엔 이름과 쓰임만 적습니다.

### 표면 — 배경보다 밝아야 계층이 보인다

| 토큰 | 용도 |
|------|------|
| `page` | 페이지 배경 |
| `surface-1` | 카드 |
| `surface-2` | 입력 · 말풍선 · 컴포저 |
| `surface-3` | hover |

### 경계 · 글자

| 토큰 | 대비(`page` 기준) | 쓰임 |
|------|------|------|
| `line` | 1.3:1 | 면 구분. **텍스트에는 쓰지 않습니다** |
| `line-strong` | 1.7:1 | 활성 보더 |
| `ink` | 15.2:1 | 본문 |
| `ink-muted` | 5.4:1 | **보조 텍스트의 단일 표준** |
| `ink-faint` | 2.9:1 | 읽지 않아도 기능이 유지되는 곳 (역할 라벨) |
| `accent` | 16.9:1 | 전송 버튼 · AI 표시점 |
| `danger` | — | 잠금 실패 · API 오류 |

`ink-faint` 에는 읽어야 할 정보를 넣지 않습니다. 곱게 보이면 `ink-muted` 로 올립니다.

### 깊이 = 상단 하이라이트, 그림자가 아니다

검은 배경에 검은 그림자는 안 보입니다. 그래서 `shadow-edge`
(`inset 0 1px 0 흰색 5.5%`)를 씁니다. **바깥 드롭 그림자는 쓰지 않습니다.**

### 강조색은 한 화면 한 곳

`accent` 는 여기저기 뿌리면 값이 0입니다. 규칙:

- **전송 버튼 1곳**, **AI 라벨 앞의 4px 점 1곳.** 그 외에는 쓰지 않습니다.
- hover·focus·선택 상태는 회색(`surface-3` / `line-strong`)으로 합니다.
- 예외: 선택됨을 나타내는 5% 틴트(`accent/5` + `accent/40` 보더)는 상태 표시로 허용합니다.

### 비활성은 흐리게 하지 않는다

`opacity-40` 으로 흐리게 하면 "일시적으로 안 되는 것"이 아니라 "망가진 것"으로 읽힙니다.
배경을 비우고(투명 + 점선 보더 + `shadow-edge` 없음) 물러나게 합니다.

### 비조명은 흐려지지 않는다

연출용 스크롤 스켈레톤을 넣지 않습니다. 데이터가 0개일 때는
"대화를 시작해보세요"처럼 **무엇을 하면 되는지 말하는 문장**을 씁니다.

### 폰트

| 역할 | 폰트 | 제공 |
|------|------|------|
| 제목 · 라틴 | IBM Plex Sans | `next/font/google` |
| 본문 라틴 · 숫자 | IBM Plex Mono | `next/font/google` |
| 한글 (전부) | Pretendard | `next/font/local` (자체 호스팅) |

**스택 순서가 곧 한글이 어디로 떨어지느냐를 정합니다.**

```css
--font-body:    var(--font-plex-mono), var(--font-pretendard), sans-serif;
--font-display: var(--font-plex-sans), var(--font-pretendard), sans-serif;
```

IBM Plex는 한글 글리프가 없습니다. Pretendard 자리를 비워 두면 화면의 모든 한글이
generic `monospace`로 폴백합니다(Windows면 Courier — 본문이 기계폰트로 보이던 그 상태).

Pretendard가 Google Fonts에 없으므로 `next/font/local` 로 직접 호스팅합니다.
CDN `<link>` 는 폰트마다 새로 걸리고 FOUT가 생기므로 쓰지 않습니다.
Variable 폰트이므로 `weight: '45 920'` 을 반드시 명시합니다.

**`next/font`는 리터럴 폰트 이름을 노출하지 않습니다. CSS 변수로만 접근합니다.**

```tsx
// ❌ 동작하지 않음
style={{ fontFamily: "'IBM Plex Sans'" }}
// ✅
className="font-display"
```

> 변수를 참조하는 테마 변수는 반드시 `@theme inline` 으로 선언해야 합니다.
> 일반 `@theme` 이면 `var()` 가 `:root` 에 박혀 런타임에 폰트 변수를 못 찾습니다.

### 에러를 말풍선에 넣지 않는다
provider의 원본 JSON이 AI 대답처럼 보이던 것을 막기 위한 것입니다.
에러는 `danger` 토큰의 **별도 영역**에 표시하고, AI 말풍선과 절대 섞지 않습니다.

## 4. 코드

- **TypeScript 필수.** `any` 지양. 명시적 타입.
- 페이지 파일은 `'use client'`를 명시적으로 붙입니다.
- `app/layout.tsx`에 `'use client'`를 붙이지 않습니다. 하위 트리 전체가
  클라이언트 렌더링으로 바뀌고 `metadata`를 쓸 수 없게 됩니다.
- 코드가 이미 말하는 것을 문서에 다시 쓰지 않습니다. 중복은 반드시 어긋납니다.

## 5. 문서

**이 저장소의 문서는 4개입니다 (`README.md` + `docs/` 3개).** 새로 늘리지 않습니다.

- **합계 400줄을 넘으면 그때 의심하세요.** 넘었다면 삭제할 게 있다는 뜻입니다.
- 지금이라도 **파일에 없는 것은 문서에 쓰지 않습니다.** 정의를 옮겨 적는 것이지,
  이미 코드에 있는 것을 옮겨 적는 것이 아닙니다.
- **판단 근거는 코드가 있는 자리에 둡니다.** 되돌릴 만한 판단일수록
  그 판단을 내린 코드 옆에 이유를 씁니다 (`components/AuthGate.tsx`가 예입니다).
  문서와 코드가 갈라지면 문서가 먼저 거짓말이 됩니다.

## 6. 커밋과 버전

- 브랜치 `master`. 혼자 쓰는 개인 저장소라 분기 이력은 필요 없습니다.
- 커밋 메시지: `v{버전} {요약}`
- **판단이 필요하면 코드를 고치기 전에** 그 판단이 들어갈 코드 옆에 적습니다.
- 검증은 `npm run lint`(경고 0) · `npx tsc --noEmit` · `npm test` · `npm run build` 통과 후에만.
  - **`npm test`가 없던 시기가 있었습니다.** 그때는 앞의 셋이 전부였는데, 셋 다 테스트가 아닙니다.
    tsc와 lint는 "의도가 읽히는 코드"만 검사합니다. `lib/context.ts`의 `estimateTokens`가
    나누는 수를 4에서 3으로 바꿔도 셋 다 통과하고, provider가 400을 내기까지 아무도
    모릅니다. 실제로 그런 사고가 났습니다 (2026-10-01, groq "Requested 46197").
- 커밋 전에 `git status`에 `.env` / `.env.local`이 없는지 확인합니다.

| 버전 올릴 때 | 기준 |
|--------------|------|
| patch | 버그 수정, 문서 정정 |
| minor | 기능 추가 |
| major | API 계약처럼 호환성이 깨지는 변경 |

`package.json`의 `version`이 기준이고, 같은 문자열로 git 태그를 붙입니다.
